# Stages 108-110

## Stage 108 - error presentation boundary

- Moved the wx error dialog implementation to `gui/dialogs/errors.py`.
- Retained `misc/errors.py` as a compatibility facade.
- Redirected canonical GUI consumers to the GUI-owned error dialog.
- Removed the wx error-dialog dependency from `processing/nmrpipe_scripts.py`;
  processing validation failures retain their existing return semantics and are
  now logged by the processing layer.

## Stage 109 - NMRPipe execution boundary

- Moved wx progress/output orchestration for NMRPipe execution to
  `gui/dialogs/processing/execution.py`.
- Added `gui/dialogs/processing/nmrpipe_adapter.py` as the GUI adapter around
  the script-generation helper.
- Canonical NMR/processing GUI code now uses the GUI adapter.
- `processing/nmrpipe_scripts.py` no longer imports wx or the shell-output
  dialog at module scope.  Its historical `execute_process_script` function is
  retained only as a compatibility bridge.

This separates two responsibilities that had grown together: generation and
manipulation of processing scripts versus wx orchestration of their execution.

## Stage 110 - compatibility-surface guard

- Added regression protection requiring `Frames/` to remain a thin historical
  compatibility package rather than becoming an implementation home again.
- Added equivalent protection for the principal root-level compatibility
  modules.
