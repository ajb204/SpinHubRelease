# Stages 138-140 - Retire MAGMA and legacy Slice4D

## Decision

MAGMA and the historical Slice4D viewer are no longer active application
features.  Their implementations are preserved for later scientific recovery.
The Slice4D code is tightly coupled to MAGMA and legacy `conn_data`, so it is
retired as a unit rather than mechanically migrated into the modern service
architecture.

The Full Peak List remains the authoritative peak collection.  `conn_data`
remains compatibility-only state.  A future restored 4D/NOE workflow should
use a dedicated connection model that references canonical Full Peak List
identities.

## Stage 138 - MAGMA quarantine

- Preserved MAGMA workspace/results implementations under `legacy/magma/`.
- Replaced `integrations/magma/*` with compatibility facades.
- Removed MAGMA imports and construction from the active notebook.
- Retained `AddMagmaTab` only as an explicit retired compatibility hook.

## Stage 139 - Slice4D quarantine

- Preserved the historical Slice4D implementation under `legacy/slice4d/`.
- `gui/workspaces/slice4d.py` is now a compatibility facade only.
- Removed Slice4D from the active slice workspace exports.
- 4D reference-list loading no longer automatically launches the legacy
  Slice4D/MAGMA viewer.
- Retained `AddTabFour4D` only as an explicit retired compatibility hook.

## Stage 140 - Regression contracts

- Added tests that MAGMA is absent from active notebook construction.
- Added tests that Slice4D is quarantined with its MAGMA/conn_data behaviour.
- Updated earlier architecture tests so retired MAGMA is no longer classified
  as an active PDF/text-viewer consumer.
