# Stages 120-124

## Stage 120 - project summary presentation ownership

Project summary generation depends on live wx/matplotlib workspace state, so its
canonical implementation moved from `project/summary.py` to
`gui/reporting/project_summary.py`.  `project/summary.py` remains a module alias
for compatibility, including historical imports of private report helpers.
The NMR workspace now imports the GUI reporting implementation directly.

## Stage 121 - project GUI launch boundary

wx application ownership moved out of `project/service.py` into
`app/launcher.py`. `ProjectService` remains the stable path/project integration
API, but delegates GUI opening to `open_project_gui`. This makes the project
package importable without wxPython while preserving embedded SpinHub and
standalone MainLoop behaviour.

## Stage 122 - workflow action routing ownership

The wx-backed `WorkflowController` moved from `workflow/actions.py` to
`app/workflow_controller.py`. The old workflow path is a compatibility alias.
Workflow definitions/status remain in the workflow package; application GUI
routing now belongs to the app layer.

## Stage 123 - workflow overview presentation ownership

The wx `WorkflowOverviewPanel` moved from `workflow/overview.py` to
`gui/workspaces/workflow.py`. The workflow package retains a compatibility
alias, while its model/status implementation is presentation-independent.
Source-contract tests now inspect the canonical GUI workspace.

## Stage 124 - GUI-independence guard

Added regression guards requiring the complete `project/` and `workflow/`
packages to remain free of wx imports. GUI lifecycle/presentation belongs to
`app/` and `gui/` respectively.
