# Stages 103-107

## Stage 103 - Text/log viewer ownership and latent import repair

The generic wx text-file/log viewer now lives at `gui/dialogs/text_viewer.py`.
`misc/textEdit.py` is a compatibility alias. MAGMA consumers use the canonical
GUI path. During this migration an existing latent runtime defect was found in
CPMG and Decay: both called `textEdit.MyFrame(...)` without importing
`textEdit`. Both now import the canonical dialog explicitly.

## Stage 104 - GUI-independent DeconService

The stdout/progress window now lives at `gui/dialogs/shell_output.py`, with
`misc/shell_output.py` retained as a compatibility alias. `DeconService` no
longer imports wx-backed shell-output infrastructure and no longer exposes the
presentation-specific `launch_with_output` method. The NMR workspace launches
the output dialog explicitly. This restores the intended dependency direction:
project service -> process/subprocess, GUI -> project service + GUI dialogs.

## Stage 105 - Project setup is a GUI dialog

The wx project-setup implementation moved from `project/setup.py` to
`gui/dialogs/project_setup.py`. The application shell uses the canonical GUI
path. `project/setup.py` and root `project_setup.py` remain compatibility
aliases for code written during earlier versions/refactor stages.

## Stage 106 - GUI status-help ownership

Status-bar hover helpers moved from `misc/status_help.py` to
`gui/widgets/status_help.py`; the old path is a compatibility alias and the
plotting toolbar uses the canonical GUI owner.

## Stage 107 - Project-core dependency guard

Added an AST regression guard asserting that the project core (`DataStore`,
state, parameter persistence, defaults and DeconService) does
not import wx or `decon.gui`. This protects the persistence/data core. `ProjectService.open()` remains an explicit application-facing integration boundary and is intentionally not included in this stricter rule.

## Validation

The full regression suite is green after every accepted boundary. Final gate:
369 passed, 1 skipped, 0 failed. Full-tree byte compilation and AST parsing are
also required before packaging.

## Next safe sequence

1. Separate GUI presentation from the remaining mixed processing modules
   (`nmrpipe_scripts.py` and `vpar_decon.py`) without changing generated-script
   semantics.
2. Split workflow presentation (`overview.py`) from workflow model/controller
   responsibilities where this can be done without wx event regressions.
3. Audit `misc/errors.py`: it is a wx error dialog currently imported by both
   GUI code and the mixed NMRPipe processing module, so move it only after the
   processing/UI boundary is explicit.
4. Continue reducing compatibility surfaces, but retain root and `Frames/`
   facades for external launch/import compatibility until a deliberate API
   deprecation release.
