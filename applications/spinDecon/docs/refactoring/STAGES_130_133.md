# Stages 130-133

## Stage 130 - Retire the disconnected uSTA tab

The historical uSTA GUI is no longer connected to the active notebook or the
special-workflow launcher. Its implementation is preserved under
`legacy/usta/workspace_legacy.py`; `integrations/usta/workspace.py` remains a
compatibility import for external callers.

This is intentionally a quarantine, not deletion. Useful scientific routines
can later be extracted into modern services. The legacy connection/`conn_data`
model is not promoted into the active architecture. The Full Peak List remains
the authoritative peak collection.

## Stage 131 - Reduce Slice1D parent-chain coupling

`SliceService` now exposes deconvolution state, dimension labels and calibrated
axis limits. The 1D slice workspace uses those service boundaries in the normal
application path instead of reaching through `parent.tabOne` for presentation
metadata.

## Stage 132 - Canonicalise the NMR workspace in ApplicationContext

`ApplicationContext.nmr_workspace` is now the canonical application-shell
reference. `legacy_nmr_workspace` remains synchronised as a deprecated
compatibility alias for external/older hosts. Workflow status resolution prefers
the canonical field before falling back to compatibility names.

## Stage 133 - Compatibility boundary guard and progress audit

A regression guard now ensures the `integrations/usta` surface remains a thin
compatibility bridge and cannot silently become an active second uSTA
implementation.

### Progress

The structural/package refactor is approximately 94-96% complete. The active
application shell, project/domain/workflow layers, analysis-service composition,
GUI workspaces/dialogs/plotting, processing boundaries, and compatibility/legacy
surfaces are established and protected by architecture tests.

Remaining code-level work is concentrated in compatibility fallbacks inside a
small set of older workspaces (peak review/fit, slices, projection/pseudo3D,
CPMG/Decay) and final processing presentation separation. CPMG/Decay contain
historical connectivity sections; these should not be mechanically promoted
because the Full Peak List is authoritative and `conn_data` remains legacy.

Before declaring completion, run the golden journeys in a wx-enabled macOS
installation with representative 1D, 2D, 3D, pseudo-2D and pseudo-3D projects.
