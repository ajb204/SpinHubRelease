# Refactoring stages 112-115

## Stage 112 - plotting asset ownership

Moved the navigation-toolbar SVG assets from `Frames/assets/` to
`gui/plotting/assets/`, beside the canonical toolbar implementation that owns
and resolves them. Removed the obsolete `Frames/assets/` copy and added a
regression test covering the complete expected icon set and toolbar lookup.

## Stage 113 - domain peak records

Moved the lightweight `peakEntry`, `connEntry`, and `diagEntry` record classes
from `misc/peaks.py` to `domain/peaks.py`. Active GUI/integration code now uses
the domain location. `misc/peaks.py` remains a compatibility facade and tests
verify class identity is preserved.

This does not change peak ownership: the Full Peak List remains authoritative.
`connEntry` is retained as a legacy/connectivity record type and does not make
`conn_data` authoritative.

## Stage 114 - peak-list file I/O ownership

Moved GUI-independent peak-list parsing from `misc/peak_io.py` to
`processing/peak_io.py`. Peak review uses the canonical processing helper;
`misc/peak_io.py` is compatibility-only.

## Stage 115 - plotting array helpers

Moved coordinate-normalisation/scatter helpers from `misc/array_utils.py` to
`gui/plotting/array_utils.py`, matching their actual use by plotting
workspaces. The historical misc module is now a compatibility facade.
